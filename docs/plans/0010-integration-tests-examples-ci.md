# Plan 0010 — Integration Tests, Examples & CI/CD

**Date:** 2026-06-06
**Type:** Formal
**Author:** Agent
**Status:** Draft
**Derivation Status:** Current

## Goal

The system is fully testable and runnable end-to-end: a comprehensive integration test suite in
`tests/` covers all eleven asset classes, the contract validation layer, determinism, look-ahead
safety, and cross-engine composition. One complete worked example exists per asset class in
`examples/`. The GitHub Actions CI pipeline runs all tests, benchmarks, and lint on every push,
and a performance regression blocks merge. `tools/` contains a fixture generator and schema
exporter. After this plan, the repository is in a state where an external contributor can clone
it, run `cargo test --workspace` and `cargo run --example <name>`, and reproduce all results.

## Scope

**In scope:**
- `tests/` — cross-crate integration tests (Rust `#[test]` in `tests/integration/`):
  - One conformance test per engine verifying key acceptance criteria against synthetic fixtures
  - Contract-validation tests: every `DataSufficiencyError` type from DATA-002 §10 step 7
  - Determinism tests: same RunRequest on 1/2/4/8 threads → byte-identical TradeRecord streams
  - Look-ahead tests: signals/features with `ts_available > current_ts` are withheld
  - Cross-engine composition test: ETF strategy using Engine A + Engine C simultaneously
  - Plan (multi-strategy) wiring test: screen→entry→exit pipeline with three strategies
- `tests/fixtures/` — complete synthetic fixture set, one per asset class:
  - Generated by `tools/gen_fixtures.rs` (deterministic, from a fixed seed)
  - All fixtures checked into the repo; generation command documented
- `examples/` — one worked example per asset class:
  - `equity_daily_crossover` (Plan 0005), plus:
  - `etf_nav_premium`, `crypto_spot_momentum`, `dex_amm_arb`, `futures_roll`,
    `perpetual_funding_carry`, `options_delta_hedge`, `bond_yield_curve`,
    `fx_carry_trade`, `nft_floor_sweep`, `prediction_market_resolution`
  - Each example is self-contained: reads from `fixtures/`, runs with no external deps,
    prints a `MetricsSummary` to stdout
- `tools/gen_fixtures.rs` — CLI tool that regenerates all fixtures from scratch (deterministic seed)
- `tools/export_schema.rs` — exports the `RunRequest` and `Strategy` JSON schemas as JSON Schema
  draft-07 files; exports `.pyi` stubs for the Python package
- DATA-008 finalization: complete the `TradeRecord` struct and the full aggregate metrics set
  (returns, Sharpe, max drawdown, Calmar, win rate, profit factor, per-capability extensions:
  funding P&L, greeks attribution, slippage/gas, Brier score)
- CI/CD finalization in `.github/workflows/`:
  - `ci.yml`: check + test + clippy + fmt on every push
  - `bench.yml`: benchmark comparison against main branch baseline on every PR
  - `examples.yml`: run all examples on every push; fail if any exits non-zero
- `procedures/verify-traceability.md` run: every spec's acceptance criteria must be cited by
  at least one test task; gaps resolved or documented as deliberate deferrals

**Out of scope:**
- Live trading or brokerage integration
- PyPI wheel publishing / versioned releases (a separate release plan)
- Distributed / cloud-scale run queue
- Full observability/telemetry (metrics exporters, dashboards)

## Risks

- Risk: DATA-008 is marked deferred; finalizing it here may require changes to `TradeRecord`
  fields that ripple through `crates/contracts`, `crates/metrics`, and all examples.
  → Mitigation: do the DATA-008 finalization first (Milestone 1) before writing tests; treat it
  as a mini design session that produces a revised spec, then update all consumers.
- Risk: Synthetic fixtures may not exercise all edge cases (e.g., options at exact expiry,
  perpetual liquidation triggered). → Mitigation: design fixtures intentionally to hit edge cases;
  document each fixture's intended coverage in `fixtures/README.md`.
- Risk: Traceability check reveals gaps (spec ACs with no test). → Mitigation: build the
  traceability check as a CI lint step that fails if any `→ SPEC-ID §N.M.X` source trace in the
  plan has no corresponding test function name. Missing tests are added, not silently omitted.
